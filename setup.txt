Student Management System - Complete A-to-Z Setup and Usage Guide

1. What This Project Is

This is an intermediate-level Student Management System built with:

-   HTML - webpage structure
-   CSS - design and responsive layout
-   JavaScript - browser-side functionality
-   Node.js - server-side runtime
-   Express.js - backend web framework
-   MySQL - relational database
-   JWT + HTTP-only cookie - login session
-   bcryptjs - password hashing

The system can be used to manage student records, attendance,
marks/results, and user roles.

This project is intended for local development and learning. It is not
configured as a production deployment package.

------------------------------------------------------------------------

2. What You Need Before Starting

You need these programs on your computer:

1.  A modern web browser
    -   Google Chrome
    -   Microsoft Edge
    -   Mozilla Firefox
2.  Node.js
    -   Install an LTS version.
    -   Node.js includes npm, which is used to install the project’s
        backend packages.
3.  MySQL Server
    -   MySQL 8.x is recommended.
    -   MySQL Server is the actual database service.
4.  MySQL Workbench (recommended)
    -   Workbench provides a graphical interface for running the SQL
        database script.
    -   You can use another MySQL client if you already know how to use
        one.
5.  The Student Management System ZIP file

You do NOT need XAMPP for this project. The backend is powered by
Node.js, and the database is MySQL.

3. Step 1 - Download and Install Node.js

Windows

1.  Open your browser.
2.  Go to the official Node.js website: https://nodejs.org/
3.  Download the current LTS version.
4.  Run the installer.
5.  Keep the default options unless you have a specific reason to change
    them.
6.  Finish the installation.

Verify Node.js

Open Command Prompt or PowerShell and run:

    node -v

You should see a version number.

Then run:

    npm -v

You should also see a version number.

If both commands return version numbers, Node.js and npm are installed
correctly.

If “node is not recognized” appears

Close Command Prompt/PowerShell and open it again.

If it still does not work, restart the computer and test again.

If the problem remains, reinstall Node.js and make sure the option that
adds Node.js to PATH is enabled.

------------------------------------------------------------------------

7. Step 5 - Install the Project Dependencies

Inside the project folder, run:

    npm install

What does this do?

The project contains a package.json file.

That file tells npm which backend packages the project needs.

npm install downloads those packages into a node_modules folder.

The first installation can take some time.

When it finishes without an error, the project dependencies are
installed.

Do not delete package.json

package.json is required to install and run the project.

The node_modules folder is generated automatically and can be very
large. It is normally not included in the ZIP/repository.

8. Step 6 - Create the MySQL Database

There are two normal ways to run the provided SQL file. MySQL Workbench
is recommended for beginners.

Method A - MySQL Workbench

1.  Open MySQL Workbench.

2.  Open your local MySQL connection.

3.  Enter the MySQL root password you created during installation.

4.  Open:

    database/schema.sql

    from the project folder.

5.  Copy its contents into a new SQL tab in Workbench, or open the file
    in Workbench.

6.  Execute the SQL script.

The script creates the required database, tables, indexes, and demo
data.

Important warning

The supplied schema.sql contains commands that can drop existing project
tables before recreating them.

Therefore:

-   Run it during initial setup.
-   If you run it again later, existing Student Management System data
    may be deleted/reset.
-   Do NOT repeatedly run it on a database containing important real
    data.

Check that the database exists

In MySQL Workbench, refresh the Schemas panel.

You should see:

    student_management

Expand it and check that the project’s tables were created.

9. Step 7 - Configure the Environment File

The project includes:

    .env.example

You need to create your own .env file.

Windows

In the project folder:

1.  Make a copy of .env.example.

2.  Rename the copy to:

    .env

Make sure the file is exactly .env, not .env.txt.

Open .env

A typical local configuration looks like:

    PORT=3000
    DB_HOST=localhost
    DB_USER=root
    DB_PASSWORD=YOUR_MYSQL_ROOT_PASSWORD
    DB_NAME=student_management
    JWT_SECRET=CHANGE_THIS_TO_A_LONG_RANDOM_SECRET

Change these values

DB_HOST

Usually:

    localhost

DB_USER

If you installed MySQL normally and use the root account:

    root

DB_PASSWORD

Replace:

    YOUR_MYSQL_ROOT_PASSWORD

with the password you created for MySQL.

For example:

    DB_PASSWORD=123456

Use your real MySQL password, not necessarily 123456.

DB_NAME

Keep:

    student_management

because that is the database created by the SQL script.

JWT_SECRET

Replace the example value with a long random secret.

Example:

    JWT_SECRET=student_management_local_secret_change_this_2026

For production, use a much longer random secret and keep it private.

Admin

The Admin account has administrative access to the management functions.

Depending on the current application implementation, administrative
functions include managing student records and accessing
dashboard/reporting features.

Faculty

protected operations.

15. Step 13 - Add a Student

To add a student:

1.  Open the Students section.
2.  Choose the add/new student option.
3.  Enter the required student information.
4.  Submit the form.
5.  The browser sends the data to the Node.js backend.
6.  The backend validates/processes the request.
7.  The backend stores the record in MySQL.
8.  The student list is updated.

Use realistic test data while developing.

------------------------------------------------------------------------

16. Step 14 - Edit a Student

To edit an existing student:

1.  Open the Students section.
2.  Find the required student.
3.  Click the edit action.
4.  Change the required information.
5.  Save the changes.

The frontend sends the update to the backend, and the backend updates
the corresponding MySQL record.

------------------------------------------------------------------------

17. Step 15 - Delete a Student

To delete a student:

1.  Find the student.
2.  Select the delete action.
3.  Confirm the deletion if the application asks for confirmation.

Be careful with deletion.

Because this is a relational database, related records such as
attendance or marks may also be affected depending on the foreign-key
rules defined in the SQL schema.

Do not use real student data until you have tested your backup/recovery
process.

Use the search/filter controls in the student management area to find

Main Node.js/Express server.

It handles:

-   API routes
-   authentication
-   student operations
-   attendance operations
-   marks operations
-   database communication
-   serving the frontend

database/schema.sql

Creates the MySQL database structure and seed/demo data.

Contains authentication/authorization middleware used to protect backend
routes.

public/index.html

Main frontend page.

Frontend styling and responsive layout.

public/js/app.js

Browser-side JavaScript that communicates with the backend API and
updates the interface.

.env.example

Example environment configuration.

.env

Your private local configuration.

Do not publish your real .env file to GitHub.

.gitignore

Lists files/folders that Git should normally ignore, such as
node_modules and .env.

24. How the Application Works Internally

The basic request flow is:

    Browser
       |
       v
    HTML + CSS + JavaScript
       |
       v
    Node.js / Express server
       |
       v
    Authentication + API logic
       |
       v
    MySQL database

Example:

When you add a student:

1.  You fill the form in the browser.
2.  JavaScript sends an HTTP request to the Node.js API.
3.  Express receives the request.
4.  Authentication middleware checks the logged-in session where
    required.
5.  The server validates/processes the data.
6.  MySQL stores the student record.
7.  The server returns a response.
8.  The frontend updates the visible student list.

25. Common Error: MySQL Connection Failed

If the terminal shows a MySQL connection error:

Check 1 - Is MySQL running?

Start the MySQL Server service.

Check 2 - Is the password correct?

Open .env and verify:

    DB_PASSWORD=YOUR_PASSWORD

Check 3 - Is the username correct?

Usually:

    DB_USER=root

Check 4 - Is the host correct?

Usually:

    DB_HOST=localhost

Check 5 - Does the database exist?

In MySQL Workbench, verify:

    student_management

Check 6 - Did you restart the Node server?

After changing .env, stop the server with Ctrl+C and start it again:

    npm start

------------------------------------------------------------------------

Node.js is not correctly installed or is not available in PATH.

Fix:

31. Security Rules for Real Use

This project is suitable for learning and local development.

Before using it with real student information:

-   Change demo passwords.
-   Use a strong random JWT secret.
-   Use a dedicated MySQL database user instead of relying on root.
-   Use HTTPS in production.
-   Protect .env.
-   Add stronger input validation.
-   Add audit logging if required.
-   Add backups and restore procedures.
-   Review role permissions.
-   Review privacy and data-retention requirements.
-   Test authorization on every protected API route.
-   Configure secure cookies for HTTPS production deployment.
-   Do not expose the MySQL server directly to the public internet.

Student information can be sensitive. Do not put real student data into
a public demo deployment without appropriate security and authorization
controls.
